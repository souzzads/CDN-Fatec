Tema 1

Complexidade de algoritmos

Big Opior casotempo e espaço

Medir um algoritmo em segundos depende do computador. Por isso contamos operações em função de n, o tamanho da entrada. A pergunta é: quando n cresce, o custo cresce como?

Big O descreve o limite superior de crescimento. Três regras resolvem a maioria dos casos: descarte constantes (2n vira n), mantenha o termo dominante (n² + n vira n²) e lembre que laços em sequência somam, laços aninhados multiplicam.

Operações para n = 1.000 (escala logarítmica)

O(1)1
O(log n)10
O(n)1.000
O(n log n)10.000
O(n²)1.000.000

Código

def soma(v):                 # O(n) tempo, O(1) espaço
    total = 0
    for x in v:
        total += x
    return total

def tem_duplicado(v):        # O(n²) tempo
    for i in range(len(v)):
        for j in range(i + 1, len(v)):
            if v[i] == v[j]:
                return True
    return False

def passos_ate_um(n):        # O(log n): n cai pela metade
    c = 0
    while n > 1:
        n //= 2
        c += 1
    return c

Espaço segue a mesma lógica: soma usa memória constante; criar uma cópia da lista usaria O(n). Também vale separar melhor, médio e pior caso: Big O costuma falar do pior.

Erros comuns

  • Achar que x in lista é O(1). É uma busca sequencial, O(n). Em set e dict é O(1) em média.
  • Esquecer que fatiar (v[1:]) copia a lista e custa O(n).
  • Tratar O(n) como "n segundos". É só a forma do crescimento.

Exercícios

Dois laços for em sequência, cada um até n. Qual a complexidade?

O(n). n + n = 2n, e a constante some.

Qual a complexidade de for i in range(n): for j in range(i): ...?

O(n²). O laço interno roda 0 + 1 + … + (n−1) = n(n−1)/2 vezes. O termo dominante é n²/2, e a constante ½ é descartada.

Se n dobra, quanto cresce o tempo de O(n), O(n²) e O(log n)?

O(n) dobra. O(n²) fica 4 vezes maior, porque (2n)² = 4n². O(log n) ganha apenas um passo extra.

Tema 2

Vetores não ordenados e busca sequencial

varredura linearsem pré-requisitoO(n)

Sem nenhuma ordem, não há atalho: o único jeito de saber que um valor não existe é olhar todos os elementos. A busca sequencial compara um a um e para no primeiro acerto.

Passo a passo

Em v = [7, 3, 9, 3] buscando 9: compara com 7 (não), com 3 (não), com 9 (sim) e devolve a posição 2, depois de 3 comparações. Buscando 5, faria as 4 comparações e devolveria -1.

def busca_sequencial(v, alvo):
    for i in range(len(v)):
        if v[i] == alvo:
            return i
    return -1

# em Python, já existe:
v.index(alvo)      # levanta ValueError se não achar
alvo in v          # True ou False
CasoQuando aconteceCusto
Melhoralvo na primeira posiçãoO(1)
Médioalvo no meio, em média n/2 comparaçõesO(n)
Pioralvo no fim ou ausenteO(n)

Quando usar: lista pequena, dados que mudam o tempo todo (manter ordenado custaria caro) ou uma única consulta. Para muitas consultas sobre dados estáveis, ordenar ou usar dict/set compensa.

Erros comuns

  • Devolver 0 ou False quando não acha. O índice 0 é válido, e if busca(...) trata a posição 0 como falha. Por isso usamos -1.
  • Dar return -1 dentro do laço, no primeiro elemento diferente. O return -1 deve ficar fora do laço.

Exercícios

Devolva todas as posições em que o alvo aparece.
def todos_indices(v, alvo):
    return [i for i, x in enumerate(v) if x == alvo]

Aqui o vetor é sempre percorrido inteiro, então o custo é O(n) em qualquer caso.

Dada uma lista de dicionários, ache o aluno pelo campo ra.
def achar_aluno(alunos, ra):
    for a in alunos:
        if a["ra"] == ra:
            return a
    return None

É a mesma ideia, devolvendo o registro em vez da posição. Em análise de dados isso aparece o tempo todo, e é onde um dict indexado por ra viraria O(1).

Quantas comparações, no pior caso, em um vetor de 500 elementos?

500. O alvo está na última posição ou não existe.

Tema 3

Vetores ordenados e busca binária

dividir pela metadeexige ordemO(log n)bisect

É o jogo de adivinhar um número de 1 a 100: você chuta 50, ouve "maior" e descarta metade das opções. Em um vetor ordenado, comparar com o elemento do meio elimina metade do que resta a cada passo, e 1 milhão de elementos cabem em cerca de 20 passos.

Veja funcionando

Código

def busca_binaria(v, alvo):
    esq, dir = 0, len(v) - 1
    while esq <= dir:
        meio = (esq + dir) // 2
        if v[meio] == alvo:
            return meio
        if v[meio] < alvo:
            esq = meio + 1      # alvo só pode estar à direita
        else:
            dir = meio - 1      # alvo só pode estar à esquerda
    return -1

A ideia que mantém tudo correto é o invariante: se o alvo existe, ele está entre esq e dir. Cada passo preserva isso e encolhe o intervalo, até achar ou esvaziar (esq > dir).

Com o módulo bisect

from bisect import bisect_left, bisect_right, insort

v = [2, 5, 8, 8, 12, 20]
bisect_left(v, 8)      # 2  (primeira posição possível)
bisect_right(v, 8)     # 4  (depois do último 8)
insort(v, 10)          # insere mantendo a ordem

bisect devolve onde o valor entraria, então para checar existência confira i < len(v) and v[i] == alvo. Note que insort acha o lugar em O(log n), mas inserir em lista ainda desloca elementos: O(n).

Erros comuns

  • Usar em vetor desordenado: a resposta pode ser errada sem nenhum erro aparente.
  • Trocar esq <= dir por esq < dir e perder o caso de um único elemento restante.
  • Esquecer o +1 e o -1 ao mover os limites, o que pode gerar laço infinito.
  • Ordenar a cada busca: ordenar custa O(n log n), então só vale ordenar uma vez e buscar muitas.

Exercícios

Quantas comparações, no máximo, em 1000 elementos?

Cerca de 10. 1000 → 500 → 250 → … → 1 leva ⌊log₂ 1000⌋ + 1 = 10 passos.

Escreva a versão recursiva.
def bb_rec(v, alvo, esq=0, dir=None):
    if dir is None:
        dir = len(v) - 1
    if esq > dir:
        return -1
    meio = (esq + dir) // 2
    if v[meio] == alvo:
        return meio
    if v[meio] < alvo:
        return bb_rec(v, alvo, meio + 1, dir)
    return bb_rec(v, alvo, esq, meio - 1)

Mesma lógica, mas a pilha de chamadas ocupa O(log n) de memória, enquanto a iterativa usa O(1).

Em [1, 4, 4, 4, 9], como achar a primeira ocorrência do 4?
from bisect import bisect_left
i = bisect_left(v, 4)
if i < len(v) and v[i] == 4:
    print(i)    # 1

A busca binária comum pode cair em qualquer um dos 4. bisect_left sempre devolve o mais à esquerda.

Tema 4

Pilhas

LIFOempilhar · desempilharestática e dinâmica

O último a entrar é o primeiro a sair (Last In, First Out), como pratos empilhados: só se mexe no de cima. Todas as operações principais são O(1).

Você usa pilhas sem perceber: o desfazer (Ctrl+Z) do editor, o botão voltar do navegador, as chamadas de função e a recursão (a "pilha de chamadas") e a checagem de parênteses em compiladores.

Implementação dinâmica

class Pilha:
    def __init__(self):
        self.itens = []

    def empilhar(self, x):
        self.itens.append(x)           # O(1)

    def desempilhar(self):
        if self.vazia():
            raise IndexError("pilha vazia")
        return self.itens.pop()        # O(1)

    def topo(self):
        return self.itens[-1]

    def vazia(self):
        return len(self.itens) == 0

Implementação estática

class PilhaEstatica:
    def __init__(self, capacidade):
        self.dados = [None] * capacidade   # tamanho fixo
        self.n = 0                         # quantos itens

    def empilhar(self, x):
        if self.n == len(self.dados):
            raise OverflowError("pilha cheia")
        self.dados[self.n] = x
        self.n += 1

    def desempilhar(self):
        if self.n == 0:
            raise IndexError("pilha vazia")
        self.n -= 1
        return self.dados[self.n]

A estática reserva a memória de uma vez e pode encher (overflow); a dinâmica cresce conforme a necessidade. Em ambas, tentar desempilhar de uma pilha vazia é underflow.

Erros comuns

  • Não checar vazio antes de desempilhar ou topo.
  • Usar pop(0) pensando em "tirar o primeiro": isso é O(n) e é comportamento de fila, não de pilha.
  • Na estática, esquecer de decrementar n ao desempilhar.

Exercícios

Verifique se parênteses, colchetes e chaves estão balanceados.
def balanceado(texto):
    p = []
    pares = {')': '(', ']': '[', '}': '{'}
    for c in texto:
        if c in '([{':
            p.append(c)
        elif c in pares:
            if not p or p.pop() != pares[c]:
                return False
    return not p

Abriu: empilha. Fechou: o topo precisa ser o par correspondente. No fim, a pilha tem que estar vazia, senão sobrou algo aberto. Teste com "([)]", que deve dar False.

Avalie uma expressão pós-fixa: "3 4 + 2 *".
def posfixa(expr):
    p = []
    for t in expr.split():
        if t in '+-*/':
            b, a = p.pop(), p.pop()
            p.append({'+': a + b, '-': a - b,
                      '*': a * b, '/': a / b}[t])
        else:
            p.append(float(t))
    return p.pop()

Números vão para a pilha; operador desempilha dois, calcula e empilha o resultado. 3 4 + vira 7, e 7 2 * dá 14. Repare na ordem: o primeiro desempilhado é o segundo operando (b).

Inverta uma string usando uma pilha.
def inverter(s):
    p = list(s)
    return ''.join(p.pop() for _ in s)

Os caracteres saem na ordem contrária à de entrada, que é a própria definição de LIFO.

Tema 5

Listas encadeadas

nó + ponteiroinserção no início O(1)sem acesso por índice

Cada elemento (nó) guarda um valor e uma referência para o próximo. Os nós ficam soltos na memória, ligados só por essas referências. Para chegar ao 5º elemento é preciso andar pelos 4 anteriores, mas inserir no início não desloca ninguém.

início → [10 | •] → [20 | •] → [30 | None]

Código

class No:
    def __init__(self, valor):
        self.valor = valor
        self.prox = None

class Lista:
    def __init__(self):
        self.inicio = None

    def inserir_inicio(self, valor):       # O(1)
        no = No(valor)
        no.prox = self.inicio
        self.inicio = no

    def inserir_fim(self, valor):          # O(n)
        no = No(valor)
        if self.inicio is None:
            self.inicio = no
            return
        atual = self.inicio
        while atual.prox:
            atual = atual.prox
        atual.prox = no

    def buscar(self, valor):               # O(n)
        atual = self.inicio
        while atual:
            if atual.valor == valor:
                return atual
            atual = atual.prox
        return None

    def remover(self, valor):              # O(n)
        atual, ant = self.inicio, None
        while atual:
            if atual.valor == valor:
                if ant:
                    ant.prox = atual.prox
                else:
                    self.inicio = atual.prox
                return True
            ant, atual = atual, atual.prox
        return False

Em remover, o ponteiro ant é o segredo: para "pular" um nó é preciso alterar o prox do nó anterior. Remover o primeiro é caso especial, pois não há anterior e é o inicio que muda.

Erros comuns

  • Religar os ponteiros na ordem errada e perder o resto da lista. Guarde prox numa variável antes de alterá-lo.
  • Esquecer o caso da lista vazia (inicio is None) e do primeiro nó.
  • Laço while atual.prox em lista vazia: atual é None e dá erro de atributo.

Exercícios

Escreva o método tamanho.
def tamanho(self):
    n, atual = 0, self.inicio
    while atual:
        n += 1
        atual = atual.prox
    return n

É O(n). Guardando um contador atualizado em cada inserção e remoção, vira O(1).

Inverta a lista sem criar uma nova.
def inverter(self):
    ant, atual = None, self.inicio
    while atual:
        prox = atual.prox       # guarda o próximo
        atual.prox = ant        # vira a seta
        ant, atual = atual, prox
    self.inicio = ant

Tempo O(n) e memória extra O(1): só as setas mudam de direção.

Ache o elemento do meio em uma única passada.
def meio(self):
    lento = rapido = self.inicio
    while rapido and rapido.prox:
        lento = lento.prox
        rapido = rapido.prox.prox
    return lento.valor if lento else None

O ponteiro rápido anda 2 nós por vez e o lento anda 1. Quando o rápido chega ao fim, o lento está no meio. É a técnica dos dois ponteiros, bem comum em prova e entrevista.
